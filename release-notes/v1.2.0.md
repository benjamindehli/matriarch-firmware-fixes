# v1.2.0: HOLD sustain fix

A second fix from Moog's v1.3.0 known-issues list: HOLD no longer sends sustain to connected gear while the Arp/Seq is playing. You can apply it together with the mixer gate fix or on its own, in the [web patcher](https://benjamindehli.github.io/matriarch-firmware-fixes/) or on the command line.

> **Unofficial. Use at your own risk.** This project isn't affiliated with or endorsed by Moog Music. This release contains no Moog firmware. You patch your own copy of Moog's official v1.3.0 file.

## Fixed

**ARP sends Sustain CC while Hold is active** (from Moog's v1.3.0 known-issues list)

Since the v1.2 updates, the HOLD button latches the Arp/Seq when it's running and works as a sustain pedal when it isn't, sending MIDI CC 64. Firmware v1.3.0 sends the sustain in both cases, so latching an arpeggio also made connected synths sustain every note. With the fix, connected gear sustains exactly when HOLD is on and the Arp/Seq isn't running:

| You do this                        | v1.3.0 sends                      | Patched sends                                 |
| ---------------------------------- | --------------------------------- | --------------------------------------------- |
| HOLD on, Arp/Seq stopped           | Sustain on                        | Sustain on                                    |
| HOLD on while the Arp/Seq plays    | Sustain on                        | Nothing, and the pattern latches as before    |
| Start the Arp/Seq while HOLD is on | Nothing, so notes keep sustaining | Sustain off, unless the sustain pedal is down |
| Stop the Arp/Seq while HOLD is on  | Nothing                           | Sustain on                                    |
| HOLD off                           | Sustain off                       | Sustain off                                   |

The Matriarch's own sound, the sustain pedal and incoming MIDI sustain work exactly as before. The fix has been tested on a Matriarch driving a Yamaha DX7 over MIDI, together with the 5 ms mixer gate fix.

Without the patch, there's a workaround: after latching with HOLD, press and release the sustain pedal. That sends sustain off to connected gear while the pattern stays latched.

## New

- **Choose your fixes in the web patcher.** Each fix has its own checkbox, and both are selected by default. The page recognises files that already have either fix and asks for Moog's original file instead.
- **`tools/patch.py`** applies one or more fixes in one command:
  ```sh
  python3 tools/patch.py Matriarch_Firmware_v1_3_0.syx Matriarch_Firmware_v1_3_0_patched.syx --mixgate 5 --hold
  ```
- The fixes change separate parts of the firmware, so the result is the same whichever order they're applied in. The tests check this.

## Changed

- The "Is it safe" answer on the website now covers both fixes. The mixer gate fix changes one number, and the HOLD fix adds a few instructions in unused flash. The rest of the firmware stays byte-identical to Moog's file.
- The README explains how the HOLD fix works, and documents that the Matriarch computes its own firmware checksum after an update.
